# 常见的加密算法

# 背景

工作中经常需要用到加密算法，比如md5、AES、RSA，也了解一点对称加密、非对称加密的概念，但是对每种算法的原理、性能、应用场景没有一个系统的了解。

现对常见的加密算法进行汇总整理，便于后续工作使用。

常见的加密算法：

  • 对称加密：DES、3DES、AES
  • 非对称加密：RSA、DSA
  • 散列算法：SHA-1、MD5

# 摘要算法

# MD5算法

MD5 （Message Digest Algorithm 5 ）用的是 哈希函数，它的典型应用是对一段信息产生 信息摘要，以 防止被篡改。严格来说，MD5 不是一种 加密算法 而是 摘要算法 (opens new window)。无论是多长的输入，MD5 都会输出长度为 128bits 的一个串 (通常用 16 进制 表示为 32 个字符)。

# SHA1算法

SHA1 （Secure Hash Algorithm 1）是和 MD5 一样流行的 消息摘要算法 (opens new window)，然而 SHA1 比 MD5 的 安全性更强。对于长度小于 2 ^ 64 位的消息，SHA1 会产生一个 160 位的 消息摘要。基于 MD5、SHA1 的信息摘要特性以及 不可逆 (一般而言)，可以被应用在检查 文件完整性 以及 数字签名 等场景。

# HMAC算法

HMAC 是密钥相关的 哈希运算消息认证码（Hash-based Message Authentication Code），HMAC 运算利用 哈希算法 (opens new window) (MD5、SHA1 等)，以 一个密钥 和 一个消息 为输入，生成一个 消息摘要 作为 输出。

HMAC 发送方 和 接收方 都有的 key 进行计算，而没有这把 key 的第三方，则是 无法计算 出正确的 散列值的，这样就可以 防止数据被篡改。

HMAC必须有秘钥才能生成摘要，可以防止伪造。

# 使用场景

核心能力：生成数据指纹，不可逆，无法还原原文

  1. 数字签名配套（HTTPS 证书、电子签章） 原文→哈希计算得到摘要 → 使用私钥对摘要签名（不会直接对大原文签名）。示例：SHA256-RSA、SM3-SM2 证书签名。
  2. HMAC 接口鉴权（开放 API：阿里云、微信支付等） 请求参数 + 密钥，通过HMAC-SHA256/HMAC-SM3生成签名；实现报文防篡改、校验调用方身份。
  3. 文件 / 报文完整性校验 文件离线传输时预先保存 SHA256 指纹；接收端重新计算摘要比对，判断内容是否被篡改。
  4. 密钥派生、随机数种子处理 从原始密钥材料派生出子密钥，用于密码学内部处理。

# 对称加密算法

AES、DES、3DES 都是 对称 的 块加密算法，加解密 的过程是 可逆的。常用的有 AES128、AES192、AES256

# DES算法

DES (Data Encryption Standard)加密算法是一种 分组密码，以 64 位为 分组对数据 加密，它的 密钥长度 是 56 位，加密解密 用 同一算法。

DES 加密算法是对 密钥 进行保密，而 公开算法，包括加密和解密算法。这样，只有掌握了和发送方 相同密钥 的人才能解读由 DES加密算法加密的密文数据。因此，破译 DES 加密算法实际上就是 搜索密钥的编码。对于 56 位长度的 密钥 来说，如果用 穷举法 来进行搜索的话，其运算次数为 2 ^ 56 次。

已淘汰，可以暴力破解，只存在于老旧系统

# 3DES算法

Triple Data Encryption Algorithm 是基于 DES 的 对称算法，对 一块数据 用 三个不同的密钥 进行 三次加密，强度更高。

DES 的过渡替代品，NIST 已经废弃推荐，速度很慢，新项目不要用

# AES算法

AES (Advanced Encryption Standard) 加密算法是密码学中的 高级加密标准，该加密算法采用 对称分组密码体制，密钥长度的最少支持为 128 位、 192 位、256 位，分组长度 128 位，算法应易于各种硬件和软件实现。这种加密算法是美国联邦政府采用的 区块加密标准。

AES 本身就是为了取代 DES 的，AES 具有更好的 安全性、效率 和 灵活性。

# 使用场景

核心能力：同一密钥完成加密和解密，运算速度快，适合大批量数据

  1. 数据库敏感字段加密存储 手机号、身份证号、银行卡、病历等敏感数据入库前加密，读取后解密。
  2. 接口报文加密传输（非 HTTPS 场景） 内部服务通信，业务 JSON 报文使用 AES-GCM 加密，避免明文传输。
  3. 文件、大附件加密 本地文件、对象存储 OSS 附件加密。
  4. HTTPS TLS 通信 TLS 握手协商临时 AES 密钥，浏览器与服务器之间业务流量通过 AES 加密传输。

# 非对称加密算法

# RSA算法

RSA （Rivest–Shamir–Adleman 取自三位发明者名字）加密算法是目前最有影响力的 公钥加密算法，并且被普遍认为是目前 最优秀的公钥方案 之一。RSA 是第一个能同时用于 加密 和 数字签名 的算法，它能够 抵抗 到目前为止已知的 所有密码攻击，已被 ISO 推荐为公钥数据加密标准。

RSA 加密算法 基于一个十分简单的数论事实：将两个大 素数 相乘十分容易，但想要对其乘积进行 因式分解 却极其困难，因此可以将 乘积 公开作为 加密密钥。

注：RSA不用于加密长文本，一般用来加密AES秘钥，而AES用来加密真实业务数据。

RSA加密流程简介：

  1. 你偷偷选两个秘密质数 p q
  2. 算出公开 n；算出秘密数字 φ(n)
  3. 选出公开的上锁指数 e（公钥）
  4. 靠 φ(n) 算出秘密解锁指数 d（私钥）
  5. 别人拿 (e,n) 锁消息；你拿 (d,n) 解锁消息
  6. 外人只知道 e 和 n，很难反向算出 d，打不开消息

RSA加密算法每次选用的的两个大素数是程序随机生成的，而1024位的素数数量在10的305次方这个数量级，计算机逐个去破解几乎不可能，这就保障了秘钥的安全性。

当年 RSA 公司搞了 RSA 挑战，放出一批 n，谁分解出来拿奖金：

  • RSA-155（512bit）：2003 年分解成功 → 512 位彻底淘汰
  • RSA-768（768bit）：2009 年，多国团队用大量 CPU 集群，花了差不多 2 年才算完，768 位作废
  • RSA-250（829bit）：2020 年分解
  • RSA-260（862bit）：2026 年被分解，目前公开分解最大纪录
  • RSA-1024（1024bit）：官方挑战至今没有公开完整分解成功的记录，只是学术界认为现在算力已经有机会攻破，工程上早已禁止使用
  • RSA-2048：目前没有任何人、任何超级计算机完成公开分解。现代互联网证书、接口用的最低标准就是 2048 位 RSA。(2048位是指pq相乘得到的二进制数字的位数)

# ECC算法

ECC （Elliptic Curve Cryptography 椭圆曲线密码算法）也是一种 非对称加密算法 (opens new window)，主要优势是在某些情况下，它比其他的方法使用 更小的密钥，比如 RSA 加密算法，提供 相当的或更高等级 的安全级别。不过一个缺点是 加密和解密操作 的实现比其他机制 时间长 (相比 RSA 算法，该算法对 CPU 消耗严重)。

ECC算法的理论依据是椭圆曲线离散对数问题：

  1. 在一条特殊的椭圆曲线（y²=x³+ax+b）上，定义了一套点的 “加法” 规则。
  2. 选一个固定起点 G（基点）。
  3. 私钥是一个很小的整数 k（比如 256bit）
  4. 公钥 = 把点 G，在曲线上连续加 k 次，得到点 P。 (P = k \times G)

难点：

​ ✅ 已知 k，算 P 非常快

​ ❌ 已知 G 和 P，反向算出 k 极其困难（椭圆曲线离散对数问题）

RSA从功能上两个秘钥都可以做运算，互相可以还原，而ECC功能上不能互换，这是最大区别。

秘钥安全性对比

ECC 曲线（私钥比特） 等效 RSA 模数长度 说明
P-256（secp256r1） RSA 2048 ✅ 互联网 HTTPS 主流，阿里云 ECC 证书就是这个
P-384（secp384r1） RSA 3072 更高安全，政府 / 金融场景
P-521（secp521r1） RSA 4096 最高 NIST 标准 ECC，性能开销更大
SM2（国密 ECC，256bit） RSA 2048 国内商用密码，256 比特

# 使用场景

核心特点：公私钥成对，运算性能低，仅处理少量短数据，禁止加密大报文

  1. SSL/TLS 证书，网站身份认证 证书内保存公钥，服务器保管私钥；浏览器校验服务器身份。现代 TLS 一般使用 ECC/RSA 做签名，ECDHE 协商对称密钥。
  2. 安全分发对称密钥（混合加密） 业务流程：生成一次性 AES 随机密钥 → 使用接收方公钥加密该 AES 密钥，连同业务密文一起传输；接收方用私钥解密得到 AES 密钥，再用 AES 解密业务大数据。（混合加密，主流开发方案）
  3. 数字签名（具备不可否认性） 合同、订单、支付报文：业务系统使用私钥对摘要签名；接收方使用公钥验签，证明报文发送方，防止抵赖。
  4. 加密少量短敏感数据 可加密密钥、一次性验证码等短内容；不可加密长文本

# 国密算法

# SM2（国密椭圆曲线公钥密码，非对称）

属于椭圆曲线密码 ECC，数学难题是椭圆曲线离散对数问题。 在一条国产定制椭圆曲线上：

  • 公开基点 G；私钥是 256 位整数k（秘密）
  • 公钥 (P = k\times G)（曲线上的点加法，前面讲 ECC 的 “跳步”） 已知k快速算出 P；已知 G、P，很难反向求出k。 可实现：数字签名、密钥协商、公钥加密。

对标 ECC secp256r1(P-256)；安全强度约等于 RSA 2048

# SM3（国密哈希 / 杂凑算法）

哈希摘要算法。输入任意长度的消息，经过多轮压缩迭代，固定输出256bit（32 字节）摘要。 雪崩效应：原文改 1bit，摘要大幅度变化；具备抗碰撞能力。 可用来生成摘要，也支持 HMAC-SM3。

对标 SHA-256，安全强度相当

# SM4（国密对称分组加密算法）

分组对称密码，分组长度 128bit，密钥 128bit。 一共 32 轮非线性迭代变换，把 128bit 明文块加密成 128bit 密文块。 支持多种工作模式：GCM、CBC、CTR。推荐 GCM（AEAD，加密自带完整性校验）。 同一个密钥，加密和解密互逆。

对标 AES-128

# 小结

类别 算法 公开性 对标国际算法 核心用途
对称分组 SM1 不公开 AES-128 硬件密码机、政务芯片
对称分组 SM4 公开 AES-128 业务报文、存储加密
对称分组 SM7 不公开 AES-128 IC 卡、门禁一卡通
流密码 ZUC 祖冲之 公开 ChaCha20 4G/5G 移动通信
非对称 SM2 公开 ECC P-256 国密证书、电子签章、密钥协商
非对称 SM9 公开 IBC 标识密码 物联网轻量化认证
哈希杂凑 SM3 公开 SHA256 摘要校验、HMAC、签名摘要

# 密码存储加密算法

# bcrypt（推荐，上手简单）

原理： 基于 Blowfish 分组密码改造，人为降低计算速度。

  1. 自动生成随机 salt
  2. 把密码 + salt，执行多次 Blowfish 迭代运算
  3. 输出结果自带版本、cost 代价因子、salt、哈希串，直接存入数据库
  • cost：代价参数（迭代次数，越大越慢，越难爆破），一般设置 10~12 优点：自带 salt，实现简单；自动截断密码 72 字节（超长密码会被截断，小缺点）

示例存储字符串： $2b$10$vI8aWBnW3fID.ZQ4/zo1G.q1lRps.9cGLcZEiGDMVr5yUP1KUOYTa

# Argon2id（现代首选）

Argon2 分为 3 个版本：

  • Argon2d：抗 GPU，但是侧信道攻击风险高
  • Argon2i：抗侧信道，GPU 爆破稍容易
  • Argon2id：混合模式，兼顾两者，密码存储标准

原理：

  1. 输入：密码、随机 salt、内存开销、迭代次数、并行度三个参数
  2. 算法会占用指定大小内存，反复读写内存做哈希运算
  3. 大量消耗【CPU + 内存】，GPU/ASIC 爆破成本极高（Argon2 最大优势）

参数示例：内存 65536KB，迭代 3 次，并发 2

# 日常使用算法推荐

# 哈希算法

哈希算法：

  1. SHA‑256（最通用首选，证书签名、HMAC、摘要校验）
  2. SHA‑384 / SHA‑512（高安全场景）
  3. SM3（国内等保、政务、涉密场景必选国密哈希）
  4. SHA3‑256（备选，独立新算法，用于风险隔离）

# 对称加密算法

  1. AES‑128‑GCM（通用业务首选） AEAD 认证加密，加密 + 完整性校验一体，并行性能好，现代标准首选。
  2. AES‑256‑GCM（高敏感数据：用户隐私、密钥、金融数据）
  3. ChaCha20‑Poly1305（无 AES 硬件加速场景：移动端、嵌入式、物联网）
  4. SM4（国内等保 / 政务国密场景）

# 非对称加密算法

  1. ECC P‑256（secp256r1）：现代互联网首选，同等安全，密钥短，速度快（TLS 证书、签名）
  2. RSA‑2048：兼容性最强，老系统对接必备；最低底线，不建议低于这个长度
  3. P‑384 / RSA‑3072、RSA‑4096：高安全场景
  4. SM2：国内国密场景，替代 ECC/RSA
类别 推荐方案 淘汰 用途
对称加密 AES-128-GCM（首选）、ChaCha20-Poly1305、SM4 DES、3DES、RC4 加密业务数据、大报文
非对称 RSA2048 / ECC P-256 / SM2 RSA1024 签名、密钥交换、加密对称密钥
哈希摘要 SHA256、SHA384、SM3 MD5、SHA1 摘要、HMAC、证书签名
